# 에어갭 Python 샌드박스 교육자료

인터넷이 끊긴 사내망의 LLM은 계산을 "기억"으로 한다. 그래서 숫자가 조금만 복잡해져도 그럴듯하게 틀린다. 이 프로젝트는 사용자 PC에 작은 MCP 서버를 띄워, LLM이 계산이 필요할 때 Python에게 일을 맡기도록 만들었다. 이 자료는 그 프로젝트를 교재로 삼아 다음 세 가지를 배우도록 구성했다.

- 폐쇄망이라는 제약 아래에서 기술을 고르고 묶는 법
- 한 시스템을 정적·동적·배포 관점으로 나누어 기술하는 아키텍처 문서 작성법
- 성능이 넉넉하지 않은 LLM을 상대로 도구를 설계할 때 부딪히는 문제와 해법

## 누구를 위한 자료인가

프로젝트를 이어받아 유지보수할 개발자, 또는 "LLM + 로컬 실행 환경"을 비슷하게 만들어 보려는 사람을 염두에 두었다. Python 코드를 읽을 수 있고 프로세스, 스레드, HTTP 정도의 개념을 알면 충분하다. MCP나 Jupyter 커널은 몰라도 된다. 필요한 만큼은 2장에서 설명한다.

## 읽는 순서

처음 보는 사람은 1장부터 차례로 읽으면 된다. 3장 본문 곳곳에 관련 ADR 번호를 달아 두었으니, "왜 이렇게 했지?" 싶은 대목에서 ADR로 건너가 읽고 돌아오기를 권한다.

이미 코드를 만져 본 사람이라면 4장과 ADR부터 읽어도 좋다. 이 프로젝트에서 가장 많이 고쳐 온 부분이 그쪽에 모여 있다.

각 장 끝에는 "생각해 볼 문제"를 붙였다. 정답을 맞히는 문제라기보다 토론거리에 가깝다. 스터디로 진행한다면 장마다 한두 문제를 골라 이야기해 보면 된다.

## 이 자료의 표기 약속

- 기준 버전은 **v0.7.0**(2026-09-22)이다. 이후 버전에서는 세부 수치가 달라질 수 있다.
- 소스 파일이나 함수 이름 대신 역할 이름(실행 코어, 커널 풀, 산출물 탐지기 같은)으로 부른다. 구현을 파일 단위로 따라가고 싶다면 저장소의 `wiki/02-components.md`를 보면 된다.
- LLM과 사용자가 직접 보는 이름은 외부와의 약속이므로 그대로 쓴다. 도구 이름(`execute_python_code`), 상태 값(`RAN_UNVERIFIED`), 환경 변수(`SANDBOX_WORKSPACE`)가 여기에 해당한다.
- 다이어그램은 Mermaid로 그렸다. GitHub, GitLab처럼 Mermaid를 렌더링하는 곳이나 VS Code(Mermaid 확장 설치 시)에서 열면 그림으로 보인다. C4 다이어그램은 Mermaid의 C4 문법을 썼다.

## 출처

저장소의 `wiki/`, `README.md`, `BUILD_PORTABLE_PACKAGE.md`, 최초 명세인 `CLAUDE.md`, 그리고 커밋 기록을 바탕으로 썼다. ADR은 결정 당시에 따로 남긴 문서가 아니다. 커밋 메시지와 위키에 흩어진 결정의 흔적을 모아 사후에 복원했다. 근거가 짧게만 남은 결정은 해당 ADR 본문에 그렇다고 밝혀 두었다.
