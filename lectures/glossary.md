# 용어집

교육자료 전체에서 사용하는 주요 핵심 용어들을 가나다순으로 정리했습니다. 괄호 안은 공식 영문 표기나 원문 명칭입니다.

| 핵심 용어 | 용어의 정확한 개념 정의 |
|---|---|
| 경로 검증기 (Path Guard) | 파일 조작 도구가 전달받은 경로를 워크스페이스 경계 내부로 엄격히 제한하는 보안 컴포넌트입니다. 이미 존재하는 파일(스크립트 실행)과 새로 생성할 파일(텍스트 저장)을 서로 다른 기준으로 정밀하게 검사합니다. |
| 계측 훅 (Instrumentation Hooks) | 커널 프로세스가 시작될 때 백그라운드에 사전 주입하는 감시 장치입니다. 일반 try-except 블록을 우회하는 스레드 예외, 하위 프로세스의 비정상 종료, `os.system` 실패 사건을 사건 장부에 기록합니다. |
| 관습적 샌드박스 (Conventional Sandbox) | 운영체제 커널 수준의 완전 강제 격리(컨테이너, 가상머신 등) 없이, 소프트웨어 규칙, 경로 검증, 엄격한 시간 예산 등의 완화책을 조합하여 운영하는 경량 실행 환경입니다. 절대적인 보안 경계는 아닙니다. |
| 네임스페이스 (Namespace) | 사용자의 개별 대화 세션에 1:1로 대응하는 논리적 실행 격리 단위입니다. 네임스페이스마다 독립된 Jupyter 커널이 배정되며, `ns-3fa1`과 같은 고유 세션 ID를 사용합니다. |
| 도구 (Tool) | MCP 서버가 LLM 에이전트에 외부에 제공하는 단일 기능 단위입니다. 고유 이름, 역할 설명문(Description), 그리고 입력 스키마(JSON Schema)로 구성됩니다. |
| 도구 예산 (Tool Time Budget) | 단일 도구 호출 요청이 클라이언트에 최종 응답을 반환하기까지 허용되는 최대 시간입니다. 기본 45초로 설정되며, 클라이언트의 60초 강제 취소 타임아웃보다 여유 있게 짧게 책정됩니다. |
| 루프백 (Loopback) | 외부 물리 네트워크 어댑터 없이도 동일한 컴퓨터 내부 프로세스 간에 고속으로 패킷을 주고받을 수 있는 가상 로컬 IP 주소(`127.0.0.1`)입니다. |
| 미러 (PyPI Mirror) | 공용 인터넷상의 PyPI 패키지 인덱스를 사내 폐쇄망 내부로 안전하게 동기화하여 구축해 둔 사내 전용 패키지 저장소입니다. |
| 사건 장부 (Incident Ledger) | 처리되지 않은 예외를 던지지 않고 조용히 숨어버리는 런타임 실패들을 커널 메모리에 누적하는 감사 목록입니다. 매 코드 실행이 끝날 때마다 서버가 프로브 셀을 통해 안전하게 수거하고 비웁니다. |
| 사전 점검 도구 (Pre-flight Checker) | 배포 대상 환경에 필수 및 권장 데이터 분석 패키지가 온전히 존재하는지, 커널 프로세스가 정상 기동되는지, 패키지 미러 인덱스에 도달 가능한지를 일괄 검증하는 독립 CLI 도구입니다. |
| 산출물 (Artifact) | 코드 실행 과정에서 워크스페이스 내부에 새롭게 생성되거나 내용이 변경된 파일(차트 이미지, 가공된 CSV 데이터 등)입니다. LLM 반환 응답에 마크다운 링크 형태로 자동 첨부됩니다. |
| 산출물 탐지기 (Artifact Detector) | 코드 실행 전후의 워크스페이스 파일시스템 스냅샷을 정밀 대조하여 신규 생성되거나 수정된 산출물 파일을 자동으로 식별해 내는 컴포넌트입니다. |
| 설명문 (Description) | MCP 도구에 부여된 상세 역할 설명 텍스트입니다. LLM 에이전트가 이를 읽고 도구의 사용 여부와 파라미터 구성 방식을 스스로 판단하므로, 실질적인 시스템 프롬프트의 역할을 합니다. |
| 스냅샷 비교 (Snapshot Diffing) | 작업 디렉터리 내 모든 파일의 `(수정 일시, 파일 크기)` 메타데이터를 두 시점에 각각 기록하고 비교하여 변경된 파일을 찾아내는 탐지 기법입니다. |
| 에어갭 (Air Gap) | 공용 인터넷이나 외부 비인가 네트워크와 물리적·논리적으로 완전히 분리된 폐쇄망 상태를 의미합니다. 본 자료에서는 인터넷이 차단된 사내망 환경을 가리킵니다. |
| 예비 커널 (Pre-warmed Reserve Kernel) | 신규 대화 세션의 첫 실행 지연(Cold Start)을 제거하기 위해 백그라운드에 미리 기동해 둔 유휴 Jupyter 커널입니다. 신규 네임스페이스 요청이 들어오면 즉각 배정됩니다. |
| 오프라인 휠 (Offline Wheel) | 인터넷이 연결된 외부 환경에서 사전에 다운로드하여 패키징해 둔 바이너리 Python 패키지 아카이브(`.whl`)입니다. 외부 인덱스 조회 없이 폐쇄망에서 즉시 설치할 수 있습니다. |
| 워크스페이스 (Workspace) | 사용자 입력 파일과 분석 산출물 파일이 함께 저장되는 디스크 폴더입니다. 모든 네임스페이스 세션이 공유하며, 백엔드 커널 프로세스의 현재 작업 디렉터리(cwd)로 바인딩됩니다. |
| 유휴 회수 (Idle Eviction) | 설정된 유휴 제한 시간(기본 30분) 동안 아무런 도구 호출이 발생하지 않은 네임스페이스의 커널 프로세스를 종료하여 OS 메모리를 확보하는 정리 메커니즘입니다. |
| 커널 (Kernel) | 사용자의 Python 코드를 실제로 파싱하고 컴파일하여 실행하는 독립 프로세스입니다. 본 시스템에서는 IPython 커널(`ipykernel`)을 사용합니다. |
| 커널 어댑터 (Kernel Adapter) | 단일 Jupyter 커널 프로세스를 1:1로 캡슐화하여 프로세스 기동, 명령 송수신, 타임아웃 인터럽트 및 강제 재시작, 사건 장부 수거를 전담하는 제어 컴포넌트입니다. |
| 커널 풀 (Kernel Pool) | 활성 네임스페이스 세션과 커널 간의 매핑을 총괄하고, 예비 커널을 상시 보충하며, 유휴 회수 및 최대 동시 커널 개수(LRU) 상한을 집행하는 관리 컴포넌트입니다. |
| 판정 (Verdict) | 코드 실행 결과를 서버가 객관적인 관측 사실에 입각하여 등급화한 결과입니다. `RAN_UNVERIFIED`, `RAN_NO_OUTPUT`, `RAN_WITH_ERRORS`, `FAILED`, `TIMEOUT`의 5단계로 구분됩니다. |
| 포터블 Python (Portable Python) | 호스트 운영체제에 별도의 인스톨러 설치 과정 없이, 디렉터리 압축 해제만으로 즉시 독립 실행 가능한 완전 자립형 Python 배포판입니다. (본 프로젝트는 WinPython 3.13을 사용합니다.) |
| 프로브 셀 (Probe Cell) | 사용자 코드의 실행이 종료된 직후 서버가 커널 세션에 조용히 파견하는 아주 짧은 내부 감사용 코드입니다. 사건 장부와 스크립트 프로세스 종료 코드를 안전하게 수거해 옵니다. |
| ADR (Architecture Decision Record) | 중요한 소프트웨어 아키텍처 의사결정 하나를 상태, 맥락, 결정, 결과의 표준화된 구조로 간결하게 기록한 기술 문서입니다. |
| AnythingLLM | 다양한 LLM 백엔드와 연동되어 채팅, 문서 검색(RAG), 자율 에이전트 워크플로를 제공하는 데스크톱 앱입니다. 본 시스템에서 주된 MCP 클라이언트 역할을 수행합니다. |
| C4 모델 (C4 Model) | 시스템 컨텍스트, 컨테이너, 컴포넌트, 코드의 4단계 계층으로 소프트웨어 아키텍처를 시각화하여 표현하는 다이어그램 모델링 기법입니다. |
| FastMCP | 공식 MCP Python SDK에 내장된 고수준(High-level) 프레임워크입니다. 일반 함수에 데코레이터를 적용하는 것만으로 Pydantic 기반의 도구 인터페이스를 손쉽게 구축할 수 있습니다. |
| iopub 채널 | Jupyter 커널이 코드 실행 도중 발생하는 실시간 표준 출력, 최종 식 평가 결과, 런타임 예외, 커널 상태 전이 이벤트를 외부에 브로드캐스팅하는 단방향 ZeroMQ 소켓 채널입니다. |
| JSON-RPC 2.0 | JSON 포맷을 기반으로 원격 프로시저 호출(RPC)을 가볍게 표현하는 표준 규약입니다. MCP 프로토콜의 모든 메시지 교환에 사용됩니다. |
| LRU (Least Recently Used) | 메모리나 슬롯이 부족할 때 가장 오랫동안 사용되지 않은 자원을 우선적으로 교체하거나 회수하는 표준 알고리즘입니다. 커널 풀의 최대 동시 세션 수 상한 관리에 적용됩니다. |
| MCP (Model Context Protocol) | LLM 애플리케이션이 외부의 다양한 도구와 데이터 소스에 표준화된 방식으로 안전하게 연동할 수 있도록 제정된 오픈소스 프로토콜 규약입니다. |
| `msg_id` | ZeroMQ를 통해 교환되는 모든 Jupyter 메시지 헤더에 부여되는 전역 고유 식별자입니다. 특정 비동기 출력이 어떤 실행 요청에 의해 촉발된 것인지 정밀하게 필터링할 때 사용됩니다. |
| `next_action` | 도구 반환 응답 텍스트의 최하단 마지막 줄에 배치되는 핵심 필드입니다. 결과를 전달받은 모델이 다음에 즉시 취해야 할 행동 지침을 단문 명령형으로 명확히 지시합니다. |
| sLLM (Small LLM) | 파라미터 규모가 상대적으로 작고 경량화된 소형 언어 모델을 뜻합니다. 본 프로젝트가 사내 폐쇄망 환경에서 실제로 연동하여 지원하는 대상 모델을 가리킵니다. |
| stdio 전송 (stdio Transport) | 클라이언트가 서버를 로컬 자식 프로세스로 직접 구동하고, 표준 입력(stdin)과 표준 출력(stdout) 파이프를 통해 실시간으로 JSON-RPC 메시지를 교환하는 가장 안전하고 단순한 전송 방식입니다. |
| venv (Virtual Environment) | Python 가상환경 격리 디렉터리입니다. 본 시스템은 베이스 포터블 환경을 오염시키지 않기 위해 `--system-site-packages` 옵션이 적용된 사이드 venv에 추가 패키지를 동적 설치합니다. |
| ZeroMQ (pyzmq) | 고성능 비동기 메시징 라이브러리입니다. 본 시스템에서 MCP 서버 프로세스와 백엔드 Jupyter 커널 프로세스 간의 IPC 통신을 고속으로 중계하는 데 사용됩니다. |
