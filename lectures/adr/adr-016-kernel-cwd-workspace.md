# ADR-016. 커널을 워크스페이스 안에서 실행한다

## 상태 (Status)

채택됨 (Accepted) · 2026-08-28, v0.4.1

[ADR-009](adr-009-kernel-cwd-project-root.md)를 대체한다.

관련 결정: [ADR-005](adr-005-snapshot-diff-artifacts.md), [ADR-007](adr-007-rules-in-tool-descriptions.md), [ADR-010](adr-010-run-script-file.md)

## 맥락 (Context)

[ADR-009](adr-009-kernel-cwd-project-root.md)에서는 커널을 프로젝트 루트에서 실행하고 모델에게 `./workspace/` 경로를 쓰게 했다. 워크스페이스를 프로젝트 밖으로 옮기는 설정을 쓰자 세 가지 문제가 드러났다.

1. **파일이 사라졌다.** 모델의 코드가 쓴 `./workspace/chart.png`는 서버 폴더 밑에 저장되었지만, 파일 도구와 산출물 탐지기는 설정된 워크스페이스를 보고 있었다.
2. **상대 경로 설정이 호스트마다 달라졌다.** `SANDBOX_WORKSPACE`를 상대 경로로 주면 서버 프로세스의 작업 디렉터리 기준으로 해석되었다. 작업 디렉터리는 서버를 띄우는 호스트(AnythingLLM, 실행 스크립트 등)가 정하므로, 같은 설정이 호스트마다 다른 폴더를 가리켰다. 같은 폴더를 공유해야 할 다른 MCP 서버와도 어긋났다.
3. **링크가 깨졌다.** 워크스페이스가 프로젝트 밖이면 산출물 링크가 절대 경로로 만들어져 `./D:/...` 같은 쓸모없는 링크가 되었다.

스크립트 실행 도구에도 비슷한 문제가 있었다. `./workspace/x.py`를 프로젝트 루트 기준으로 풀다 보니, 워크스페이스를 옮기면 파일을 못 찾거나 프로젝트 안에 남아 있던 같은 이름의 오래된 파일을 집은 뒤 "워크스페이스 밖"이라며 거절했다.

## 결정 (Decision)

"파일이 어디 있는가"에 대한 기준점을 워크스페이스 하나로 통일한다.

- 커널을 워크스페이스를 작업 디렉터리로 해서 실행한다. 모델의 코드가 `chart.png`라고만 써도 워크스페이스에 저장된다.
- 도구 규칙을 바꾼다. 이제는 `./workspace/`를 붙이지 말고 파일 이름만 쓰라고 안내한다.
- 상대 경로로 준 `SANDBOX_WORKSPACE`는 서버 코드가 있는 폴더를 기준으로 해석한다. 호스트가 어느 작업 디렉터리에서 서버를 띄우든 같은 폴더를 가리킨다.
- 파일 도구는 `./workspace/`, `workspace/`, `/workspace/`로 시작하는 경로를 받으면 접두사를 떼고 워크스페이스 기준으로 해석한다. 옛 습관이 남은 모델도 계속 동작한다.
- 산출물 링크는 워크스페이스가 프로젝트 밖에 있어도 `workspace/<이름>` 형태를 유지한다.

## 결과 (Consequences)

**좋아진 점**

- 커널, 파일 도구, 산출물 탐지기가 모두 같은 기준점을 쓴다. 기본 설정에서만 우연히 맞던 상황이 어떤 설정에서도 맞게 되었다.
- 모델이 쓸 경로가 짧아졌다. 접두사를 잊어버려서 생기는 실수가 사라진다.
- 워크스페이스를 공유 폴더나 다른 드라이브로 자유롭게 옮길 수 있다.

**치른 비용과 남은 흔적**

- 커널 시작 코드는 여전히 작업 디렉터리 안에 `workspace` 하위 폴더를 만들어 둔다. 옛 규칙대로 `./workspace/chart.png`에 저장하는 모델의 코드가 실패하지 않게 하려는 호환 장치다. 이렇게 저장된 파일은 워크스페이스 안의 하위 폴더에 있으므로 산출물로는 정상적으로 잡힌다. 대신 워크스페이스 안에 `workspace` 폴더가 한 겹 더 생긴다.
- 사용자 문서, 규칙, 테스트를 모두 함께 바꿔야 했다. 경로 규칙은 모델, 사용자, 코드가 모두 공유하는 약속이라 한 곳만 바꿀 수 없다.

**교훈**

기본 설정에서 잘 동작한다고 해서 설계가 맞다는 뜻은 아니다. 설정으로 바꿀 수 있는 값이 있다면, 기본값이 아닌 값으로도 시험해야 한다. 이 버전에서 외부 워크스페이스 경로를 다루는 테스트가 추가된 것도 그 때문이다.
