# ADR-003. 서버 인터프리터와 커널 인터프리터를 아키텍처적으로 분리합니다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0

관련 결정: [ADR-002](adr-002-persistent-jupyter-kernel.md), [ADR-004](adr-004-portable-python-bundle.md), [ADR-019](adr-019-side-venv-installs.md)

## 맥락 (Context)

MCP 서버 프로세스를 구동하는 데 필요한 패키지는 `mcp`, `jupyter_client`, `ipykernel`의 3가지뿐입니다. 반면 사용자 코드를 실행할 Jupyter 커널 프로세스에는 pandas부터 PyMuPDF에 이르기까지 3GB가 훌쩍 넘는 방대한 데이터 사이언스 라이브러리 스택이 요구됩니다.

만약 서버와 커널을 반드시 단 하나의 동일한 인터프리터에서만 실행되도록 강제한다면, 서버를 구동할 수 있는 런타임 환경이 오직 그 무거운 포터블 Python 하나로 영구히 제한됩니다. 만약 현업 폐쇄망 PC에 데이터 분석 라이브러리가 이미 완벽히 갖춰진 사내 표준 Python이 존재하지만 관리자 권한이 없어 서버 구동용 패키지를 추가 설치할 수 없는 고정된 환경이라면, 시스템 자체를 구동할 수 있는 방법이 완전히 사라지게 됩니다.

또한 `jupyter_client`는 기본적으로 운영체제 시스템 경로에 사전에 등록된 커널 명세(kernelspec) 파일을 탐색하여 커널 프로세스를 띄웁니다. 폐쇄망 PC에 어떤 커널 명세가 등록되어 있는지 사전에 알기 어려우며, 신규 커널 명세를 OS에 등록하려면 번거로운 사전 설치 절차가 요구됩니다.

## 결정 (Decision)

백엔드 커널 프로세스를 띄울 Python 인터프리터의 실행 파일 경로를 환경 변수(`SANDBOX_KERNEL_PYTHON`)를 통해 외부에서 유연하게 주입받도록 설계했습니다. 커널 관리자(`KernelManager`)가 시스템 전역 커널 명세를 검색하는 대신, 해당 설정 경로를 기반으로 조합한 실행 명령(`<python> -m ipykernel_launcher -f <연결_설정_파일>`)을 직접 사용하도록 커널 스펙을 인메모리에서 즉각 지정합니다. 만약 환경 변수가 지정되지 않았다면 서버 프로세스 자신의 Python 인터프리터를 기본값으로 사용합니다.

아울러 MCP 서버 소스코드는 대용량 데이터 사이언스 라이브러리들을 단 하나도 직접 임포트하지 않도록 엄격히 격리했습니다.

## 결과 (Consequences)

**얻게 된 이점**

- MCP 서버 프로세스를 매우 가볍고 독립적인 상태로 유지할 수 있습니다. 이미 현장에 구축되어 있는 임의의 Python 런타임을 환경 변수 설정 하나만으로 손쉽게 가리키도록 연결할 수 있습니다.
- 호스트 운영체제에 번거로운 Jupyter 커널 명세를 별도로 사전 등록할 필요가 전혀 없습니다.
- 표준 오프라인 배포 패키지에서는 편의상 서버와 커널이 동일한 WinPython을 함께 사용하므로 사용자가 별도의 복잡한 경로를 설정할 필요가 없습니다. 그러면서도 인터프리터 분리 아키텍처는 유연한 예비 선택지로 항상 살아있습니다. 예를 들어 대상 PC의 기본 Python 환경이 읽기 전용으로 잠겨 있더라도, 서버 프로세스 자체는 다른 가벼운 Python으로 띄우고 커널만 해당 표준 Python을 가리키도록 유연하게 분리 배포할 수 있습니다.
- 이후 사내 미러 연동을 위한 사이드 venv를 구축할 때도 동일한 환경 변수 경로를 베이스 기준으로 참조함으로써, 커널 런타임과 venv의 Python 바이너리 버전이 어긋나는 문제를 원천 방지했습니다([ADR-019](adr-019-side-venv-installs.md)).

**감수한 트레이드오프**

- 커널 인터프리터 쪽에도 `ipykernel` 패키지만큼은 반드시 사전에 설치되어 있어야 합니다. 배포 사전 점검 도구가 커널 프로세스를 실제로 띄워보는 스모크 테스트를 수행하는 이유가 바로 이 의존성을 확인하기 위함입니다.
- `jupyter_client`의 공식 공개 API가 아닌 내부 속성을 오버라이드하여 커널 실행 명령을 직접 지정합니다. 향후 `jupyter_client` 라이브러리를 상위 버전으로 업그레이드할 때 가장 먼저 인터페이스 호환성을 점검해야 할 핵심 관리 포인트입니다.
- 서버 인터프리터와 커널 인터프리터를 서로 다르게 이원화하여 구성할 경우, 양측 간의 ZeroMQ 메시징 프로토콜 버전 호환성은 엔지니어가 수동으로 사전에 확인해 주어야 합니다.
