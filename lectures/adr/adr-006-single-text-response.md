# ADR-006. 도구의 모든 반환 결과는 단 하나의 일체형 텍스트 블록으로 응답합니다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0 (v0.5.0에서 정보 배치 레이아웃 전면 개편)

관련 결정: [ADR-007](adr-007-rules-in-tool-descriptions.md), [ADR-017](adr-017-execution-verdict.md)

## 맥락 (Context)

MCP 프로토콜 명세상 도구의 반환 결과에는 일반 텍스트, 이미지 바이너리, 임베디드 리소스 등 다양한 형태의 콘텐츠 블록을 복합적으로 담을 수 있으며, 정형화된 JSON 데이터 구조를 포함할 수도 있습니다. 그러나 현실에서는 MCP 클라이언트(AnythingLLM 등)마다 지원하는 미디어 타입의 범위가 제각각 다릅니다. 더욱이 어떤 복잡한 객체 포맷으로 전송하더라도, 최종적으로 언어 모델의 주의 집중(Attention) 컨텍스트에 주입되는 정보는 결국 평문 텍스트 형태로 직렬화됩니다.

본 시스템에서 모델에게 전달되어야 할 핵심 정보는 코드가 출력한 표준 출력 텍스트, 런타임 오류 및 트레이스백 내용, 생성된 산출물 파일의 접근 경로, 그리고 인터프리터 실행이 어떤 상태로 완수되었는지에 대한 판정 메타데이터입니다.

초기 시스템 요구 명세서는 이를 `stdout`, `stderr`, `artifacts`, `execution_status`라는 4가지 독립 필드로 반환할 것을 요구했습니다.

## 결정 (Decision)

모든 MCP 도구는 다중 객체나 복잡한 바이너리 대신, 정형화된 단 하나의 일체형 텍스트 블록(Single Text Block)으로 반환하기로 결정했습니다. 요구 명세서의 세부 필드들은 텍스트 내부에서 명확한 구분자 헤더(`--- stderr ---`, `--- stdout ---`, `--- last expression ---`, `--- artifacts ---`)를 가진 독립된 섹션으로 정연하게 배치합니다.

- 마지막 라인의 단독 표현식 평가값(`last expression`)은 코드가 화면에 아무것도 `print()`하지 않았을 때만 선별 노출합니다. 동일한 출력과 계산값이 중복으로 두 번 표시되어 컨텍스트를 낭비하는 현상을 방지합니다.
- stdout과 stderr는 각각 최대 20,000자(`SANDBOX_MAX_STREAM_CHARS`)까지만 안전하게 수집하며, 이를 초과할 경우 초과분이 축약(Truncated)되었음을 명확한 문구로 안내합니다.
- 실행 중 생성된 신규 파일이 없을 때는 빈칸으로 남겨두지 않고, "(no new files created in the workspace)"라는 명시적인 텍스트를 기재합니다.

## 결과 (Consequences)

**얻게 된 이점**

- AnythingLLM뿐만 아니라 향후 어떤 임의의 MCP 클라이언트에 연결하더라도 클라이언트의 파싱 버그 없이 100% 동일하고 안정적인 형태로 결과가 렌더링됩니다.
- 반환 텍스트의 물리적 공간 배치를 MCP 서버가 완벽하게 통제할 수 있습니다. 이 유연성 덕분에 v0.5.0에서 "첫 줄은 기계 판정 등급, 마지막 줄은 후속 행동 지침, 오류 stderr는 일반 출력 stdout보다 상단에 우선 배치"라는 고도화된 프롬프트 레이아웃을 성공적으로 구현할 수 있었습니다([ADR-017](adr-017-execution-verdict.md)).
- 출력 문자열 상한 필터를 통해 대량의 로그를 무한 출력하는 코드 폭주가 발생하더라도 LLM의 컨텍스트 윈도우가 한순간에 고갈되는 문제를 완벽히 방어합니다.
- 아무런 출력도 발생하지 않았다는 사실을 침묵 대신 명확한 텍스트로 고지하므로, 모델이 코드에서 `print()` 함수를 실수로 누락했다는 사실을 스스로 인지하기가 훨씬 쉬워집니다.

**감수한 트레이드오프**

- 데스크톱 클라이언트 애플리케이션이 도구 결과를 프로그램 레벨에서 기계적으로 직접 파싱하기가 다소 어렵습니다. 만약 판정 코드를 정형 데이터로 추출하려면 정규표현식 등으로 텍스트를 파싱해야 합니다. (구조화된 정형 도구 출력 지원은 향후 로드맵 과제로 관리하고 있습니다.)
- 차트 이미지 파일을 응답 내부에 직접 인라인 바이너리로 인코딩하여 반환하지 않고 마크다운 링크로만 제공합니다. 따라서 텍스트 전용 LLM 모델은 생성된 차트의 시각적 형태를 직접 확인하지 못합니다. 만약 차트가 나타내는 핵심 통계 수치를 모델이 후속 대화에서 반드시 알아야 한다면, 코드 작성 시 콘솔에도 함께 `print()`하도록 안내해야 합니다.
