# ADR-006. 도구 응답은 하나의 텍스트 블록으로 돌려준다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0 (v0.5.0에서 배치 순서 변경)

관련 결정: [ADR-007](adr-007-rules-in-tool-descriptions.md), [ADR-017](adr-017-execution-verdict.md)

## 맥락 (Context)

MCP 도구의 결과에는 텍스트, 이미지 같은 여러 콘텐츠를 담을 수 있고, 명세에 따라서는 구조화된 데이터도 담을 수 있다. 그러나 클라이언트마다 지원 범위가 다르다. 그리고 어떤 형식으로 보내든 결국 모델의 컨텍스트에 들어가는 것은 텍스트다.

이 시스템에서 모델에게 필요한 것은 코드가 출력한 텍스트, 오류 내용, 만들어진 파일의 링크, 그리고 실행이 어떻게 끝났는지에 대한 정보다.

최초 명세는 `stdout`, `stderr`, `artifacts`, `execution_status` 네 필드를 요구했다.

## 결정 (Decision)

모든 도구가 텍스트 블록 하나를 돌려준다. 명세의 필드들은 텍스트 안의 절로 표현한다. 실행 도구의 응답은 정해진 머리글(`--- stderr ---`, `--- stdout ---`, `--- last expression ---`, `--- artifacts ---`)로 절을 나눈다.

- 마지막 식의 값은 아무것도 `print`하지 않았을 때만 보여 준다. 출력과 값이 겹쳐 두 번 나오는 것을 막는다.
- stdout과 stderr는 각각 20,000자(`SANDBOX_MAX_STREAM_CHARS`)까지만 돌려주고, 넘으면 잘렸다고 표시한다.
- 새 파일이 없으면 "워크스페이스에 새로 생긴 파일이 없다"고 명시한다.

## 결과 (Consequences)

**좋아진 점**

- 어떤 MCP 클라이언트에서든 똑같이 보인다.
- 텍스트의 배치를 서버가 완전히 통제한다. 이 덕분에 v0.5.0에서 "판정은 첫 줄, 할 일은 마지막 줄, 오류는 출력보다 위"라는 배치를 도입할 수 있었다([ADR-017](adr-017-execution-verdict.md)).
- 출력 상한 덕분에 폭주하는 루프가 모델의 컨텍스트를 가득 채우지 않는다.
- "아무것도 안 나왔다"를 빈칸이 아니라 문장으로 알려 주므로, 모델이 출력을 빼먹었다는 사실을 알아채기 쉽다.

**치른 비용**

- 클라이언트가 결과를 기계적으로 읽을 수 없다. 판정 값을 프로그램으로 꺼내려면 텍스트를 파싱해야 한다. 구조화된 출력은 로드맵에 남아 있다.
- 이미지는 응답에 담지 않고 링크로만 돌려준다. 모델은 차트를 직접 보지 못한다. 차트가 보여 주는 수치를 모델이 알아야 한다면 코드에서 따로 `print`해야 한다.
