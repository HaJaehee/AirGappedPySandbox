# ADR-001. 로컬 PC에 MCP 서버를 두어 사내 LLM에 코드 실행 능력을 부여합니다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0

관련 결정: [ADR-004](adr-004-portable-python-bundle.md), [ADR-008](adr-008-conventional-sandbox-timeouts.md), [ADR-011](adr-011-namespace-argument.md), [ADR-021](adr-021-tool-time-budget.md)

## 맥락 (Context)

사내 LLM은 인터넷이 완전히 차단된 사내망 내부의 중앙 서버에서 동작하고 있습니다. 문서 요약이나 이메일 초안 작성과 같은 언어 작업은 잘 수행하지만, 복잡한 수치 계산, 단위 환산, 정형 표 데이터 분석, 다양한 포맷의 문서 파싱 작업에서는 자주 오류를 일으킵니다. 언어 모델은 학습된 가중치 패턴에 기반하여 확률적으로 답변을 생성할 뿐, 실제로 논리적 계산을 수행하지 않기 때문입니다. 업계의 표준적인 해결책은 모델에 코드 실행 도구(Code Interpreter)를 연결하여 실제 계산을 Python 인터프리터에 위임하는 방식입니다.

당시 직면했던 핵심 질문은 "그 코드 실행 도구를 시스템의 어디에 배치할 것인가?"였습니다.

일반 개발팀이나 실무 사용자에게는 중앙 LLM 서버에 대한 관리자 권한도, SSH 원격 접속 권한도 주어지지 않았습니다. 전사 인프라 관리팀에 기능 개발을 정식 요청할 경우 결재 승인과 작업 반영에 수개월 이상의 긴 시간이 소요되며, 한 번 배포된 환경은 분석 라이브러리를 하나 추가하려 해도 매번 번거로운 변경 승인 절차를 다시 밟아야만 합니다.

한편 사용자의 로컬 업무용 PC에는 AnythingLLM 데스크톱 앱이 이미 설치되어 있었고, 사내 LLM 서버와 OpenAI 호환 API로 연동되어 있었습니다. 특히 AnythingLLM의 에이전트 기능은 로컬 MCP(Model Context Protocol) 서버를 외부 도구로 등록하여 호출할 수 있는 표준 기능을 지원하고 있었습니다.

당시 검토했던 주요 대안들은 다음과 같습니다.

1. **중앙 LLM 서버 내부에 코드 실행 기능을 직접 탑재합니다.** 시스템 권한이 없어 접근이 불가능하고, 전사 요청 절차가 매우 느리며, 반영된 이후에도 환경을 변경하기가 극히 어렵습니다.
2. **사내망 내부에 별도의 중앙 집중형 코드 실행 마이크로서비스를 구축합니다.** 신규 서버 인프라 자원 확보와 까다로운 보안 승인이 필요합니다. 또한 여러 사용자의 코드를 단일 서버에서 동시에 실행하려면 고난도의 강력한 격리 환경(컨테이너, 가상머신 등) 구축이 필수가 됩니다.
3. **프롬프트 엔지니어링을 통해 모델에게 '더 신중하게 단계별로 계산하라'고 지시합니다.** 모델이 실제 계산을 수행하지 못한다는 근본적인 한계는 전혀 해결되지 않습니다.
4. **사용자 로컬 PC 내부에 독립된 MCP 서버를 구동합니다.** 사용자 로컬 계정의 기본 권한만으로도 소프트웨어를 자유롭게 설치하고 신속하게 개선해 나갈 수 있습니다.

## 결정 (Decision)

사용자 업무용 PC에서 직접 구동되는 로컬 Python MCP 서버를 구축하고, AnythingLLM이 이 서버를 표준 입출력(stdio) 방식의 로컬 자식 프로세스로 실행하도록 구성하기로 결정했습니다. 중앙의 원격 LLM 서버 환경은 단 한 줄도 수정하지 않습니다.

역할 분담은 명확합니다. 원격 LLM은 무엇을 계산할지 판단하여 Python 코드를 작성하고, 실제 코드의 실행은 사용자 로컬 PC의 Python 런타임이 담당합니다. 그리고 최종 실행 결과 텍스트만이 모델에게 전달되어 후속 추론에 활용됩니다.

## 결과 (Consequences)

**얻게 된 이점**

- 원격 인프라 설정을 전혀 건드리지 않고도, 사용자와 개발팀이 주도권을 쥐고 로컬에서 소프트웨어를 빠르게 배포하고 개선할 수 있게 되었습니다. 실제로 이후 다양한 후속 버전들이 현업 피드백을 바탕으로 신속하게 출시될 수 있었습니다.
- 분석 대상 원본 파일들이 사용자 로컬 PC를 벗어나 외부로 유출되지 않습니다. 원격 모델에는 코드가 표준 출력으로 출력한 최종 결과 텍스트만 전달되므로 사내 데이터 보안에 매우 유리합니다.
- 표준 입출력(stdio) 파이프 전송 방식을 사용하므로 외부 네트워크 포트를 개방할 필요가 없고 방화벽 정책을 변경할 필요도 전혀 없습니다.

**감수한 트레이드오프**

- 각 사용자 PC마다 개별 패키지 설치 및 환경 설정 작업이 필요합니다. 약 3.47GB에 달하는 포터블 번들을 사내 보안 절차를 거쳐 오프라인으로 반입해야 합니다([ADR-004](adr-004-portable-python-bundle.md)).
- 일반 채팅 모드가 아닌 AnythingLLM의 에이전트 모드에서만 도구를 호출할 수 있습니다.
- 모델이 작성한 임의의 코드가 사용자 계정 권한으로 로컬 PC에서 직접 실행됩니다. 이에 따라 별도의 안전장치와 격리 정책을 설계해야 했습니다([ADR-008](adr-008-conventional-sandbox-timeouts.md)).

**이후에 새롭게 드러난 파급 효과**

- AnythingLLM이 MCP 서버 프로세스를 인스턴스당 단 하나만 구동하고 모든 대화 탭이 이를 공유한다는 사실을 확인했습니다. 이로 인해 대화 세션 간 변수가 충돌하는 심각한 문제가 발생하여 네임스페이스 격리 아키텍처를 도입하게 되었습니다([ADR-011](adr-011-namespace-argument.md)).
- MCP 클라이언트 SDK가 강제하는 60초 요청 타임아웃 제한을 함께 수용해야 했습니다. 이후 시간이 오래 소요되는 패키지 설치 작업 등에서 이 제한이 중요한 설계 과제가 되었습니다([ADR-021](adr-021-tool-time-budget.md)).
