# ADR-001. 로컬 PC에 MCP 서버를 두어 사내 LLM에 코드 실행 능력을 붙인다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0

관련 결정: [ADR-004](adr-004-portable-python-bundle.md), [ADR-008](adr-008-conventional-sandbox-timeouts.md), [ADR-011](adr-011-namespace-argument.md), [ADR-021](adr-021-tool-time-budget.md)

## 맥락 (Context)

사내 LLM은 인터넷이 차단된 사내망의 서버에서 돈다. 요약이나 작문은 괜찮지만 복잡한 계산, 단위 환산, 표 데이터 분석, 여러 형식의 문서 파싱에서는 자주 틀린다. 가중치에 기억된 패턴으로 답을 만들 뿐 실제로 계산하지 않기 때문이다. 흔한 처방은 모델에게 코드 실행 도구를 붙여 계산을 인터프리터에 맡기는 것이다.

문제는 그 도구를 어디에 둘 것인가였다.

사용자에게는 LLM 서버의 관리자 권한도 SSH 접근도 없다. 인프라 팀에 요청하면 승인과 작업에 오랜 시간이 걸리고, 한 번 들어간 기능은 라이브러리 하나를 추가하는 데도 같은 절차를 다시 밟아야 한다.

한편 사용자 PC에는 AnythingLLM이 설치되어 있었고, 사내 LLM 서버에 OpenAI 호환 API로 붙어 있었다. AnythingLLM의 에이전트 기능은 로컬 MCP 서버를 도구로 쓸 수 있다.

검토한 선택지는 다음과 같다.

1. **LLM 서버에 코드 실행 기능을 넣는다.** 권한이 없고, 요청 절차가 느리며, 들어간 뒤에도 바꾸기 어렵다.
2. **사내망에 별도의 코드 실행 서비스를 세운다.** 서버 자원과 승인이 필요하다. 여러 사용자의 코드를 한 서버에서 돌리려면 강한 격리도 필수가 된다.
3. **프롬프트로 모델에게 더 신중하게 계산하라고 한다.** 모델이 계산하지 못한다는 근본 원인은 그대로다.
4. **사용자 PC에 MCP 서버를 둔다.** 사용자 권한만으로 만들고 고칠 수 있다.

## 결정 (Decision)

사용자 PC에서 도는 Python MCP 서버를 만들고, AnythingLLM이 이 서버를 stdio 방식의 자식 프로세스로 띄우게 한다. 원격 LLM 서버는 전혀 건드리지 않는다.

역할은 이렇게 나뉜다. 모델은 무엇을 계산할지 판단해 코드를 쓴다. 코드는 사용자 PC의 Python이 실행한다. 실행 결과는 텍스트로 모델에게 돌아간다.

## 결과 (Consequences)

**좋아진 점**

- 원격 인프라를 바꾸지 않고, 사용자가 스스로 배포하고 고칠 수 있다. 실제로 이후 여러 버전이 사용자 주도로 빠르게 나왔다.
- 분석 대상 파일은 사용자 PC를 떠나지 않는다. 모델에게는 코드가 출력한 결과 텍스트만 전달된다.
- stdio 전송이라 포트를 열거나 방화벽을 건드릴 필요가 없다.

**치른 비용**

- PC마다 설치가 필요하다. 3.47GB짜리 패키지를 반입해야 한다([ADR-004](adr-004-portable-python-bundle.md)).
- AnythingLLM의 에이전트 모드에서만 쓸 수 있다.
- 모델이 쓴 코드가 사용자 계정 권한으로 사용자 PC에서 돈다. 격리 수준을 따로 정해야 했다([ADR-008](adr-008-conventional-sandbox-timeouts.md)).

**이후에 드러난 일**

- AnythingLLM은 MCP 서버 프로세스를 하나만 띄우고 모든 대화가 그것을 공유한다. 이 때문에 대화끼리 변수가 충돌하는 문제가 생겼다([ADR-011](adr-011-namespace-argument.md)).
- MCP 클라이언트의 60초 요청 제한도 함께 떠안게 되었다. 오래 걸리는 설치에서 이 제한이 문제를 일으켰다([ADR-021](adr-021-tool-time-budget.md)).
