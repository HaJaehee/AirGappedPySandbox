# ADR-009. 커널을 프로젝트 루트에서 실행하고 코드는 `./workspace/` 경로를 쓴다

## 상태 (Status)

**대체됨 (Superseded)** · 2026-07-23, v0.1.0에 채택 → 2026-08-28, v0.4.1에서 [ADR-016](adr-016-kernel-cwd-workspace.md)으로 대체

관련 결정: [ADR-005](adr-005-snapshot-diff-artifacts.md), [ADR-007](adr-007-rules-in-tool-descriptions.md)

## 맥락 (Context)

최초 명세는 모든 입출력을 `./workspace/` 디렉터리 기준으로 하라고 요구했다. 규칙의 예시도 `plt.savefig('./workspace/filename.png')`였다.

당시 워크스페이스는 항상 서버 코드가 있는 프로젝트 폴더 안의 `workspace` 폴더였다. 위치를 바꾸는 설정(`SANDBOX_WORKSPACE`)은 있었지만 기본값을 쓰는 한 프로젝트 안에 있었다.

## 결정 (Decision)

커널의 작업 디렉터리를 프로젝트 루트로 둔다. 도구 설명문의 규칙에서 모델에게 모든 입출력 경로에 `./workspace/`를 붙이라고 안내한다. 이렇게 하면 모델이 쓰는 `./workspace/chart.png`가 프로젝트 안의 워크스페이스 폴더를 가리킨다.

## 결과 (Consequences)

**처음에는 잘 동작했다**

워크스페이스가 프로젝트 안에 있는 동안에는 명세의 예시와 실제 동작이 일치했고 문제가 없었다.

**설정을 바꾸자 무너졌다**

`SANDBOX_WORKSPACE`로 워크스페이스를 프로젝트 밖(예: 다른 드라이브의 공유 폴더)으로 옮기자 문제가 드러났다. 이 설정이 있는 이유가 바로 다른 곳을 가리키기 위해서인데도 그랬다.

- 모델의 코드가 쓴 `./workspace/chart.png`는 커널의 작업 디렉터리인 프로젝트 루트 기준으로 해석되어, 서버 폴더 밑에 저장되었다.
- 반면 파일 목록 도구, 스크립트 실행 도구, 저장 도구, 산출물 탐지기는 모두 설정된 워크스페이스를 보고 있었다.
- 결과적으로 파일은 만들어졌는데 어느 도구에서도 보이지 않았다. 사용자 눈에는 파일이 사라진 것처럼 보였다.

같은 시기에 비슷한 문제가 두 가지 더 발견되었다. 상대 경로로 준 `SANDBOX_WORKSPACE`가 서버를 띄운 호스트의 작업 디렉터리 기준으로 해석되어, 호스트마다 다른 폴더를 가리켰다. 워크스페이스가 프로젝트 밖일 때 산출물 링크가 절대 경로로 만들어져 `./D:/...` 같은 깨진 링크가 되었다.

**교훈**

"경로의 기준점"이 둘 이상이면 언젠가 어긋난다. 이 결정에서는 커널이 경로를 해석하는 기준(프로젝트 루트)과 도구들이 파일을 찾는 기준(설정된 워크스페이스)이 달랐다. 기본 설정에서는 두 기준이 우연히 같은 곳을 가리켜 문제가 숨어 있었다.

이 결정은 [ADR-016](adr-016-kernel-cwd-workspace.md)으로 대체되었다.
