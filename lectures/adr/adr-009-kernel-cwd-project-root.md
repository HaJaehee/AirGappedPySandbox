# ADR-009. 커널을 프로젝트 루트에서 실행하고 코드는 `./workspace/` 상대 경로를 사용합니다

## 상태 (Status)

**대체됨 (Superseded)** · 2026-07-23, v0.1.0 채택 → 2026-08-28, v0.4.1에서 [ADR-016](adr-016-kernel-cwd-workspace.md)으로 전면 대체됨

관련 결정: [ADR-005](adr-005-snapshot-diff-artifacts.md), [ADR-007](adr-007-rules-in-tool-descriptions.md)

## 맥락 (Context)

초기 시스템 요구 명세서는 모든 파일 입출력을 `./workspace/` 상대 디렉터리 기준으로 처리하도록 규정했습니다. 도구 설명문 내부의 권장 예제 역시 `plt.savefig('./workspace/filename.png')` 형태로 작성되어 있었습니다.

프로젝트 초기 당시 워크스페이스는 항상 MCP 서버 소스코드가 위치한 프로젝트 디렉터리 내부의 `workspace` 하위 폴더로 고정되어 있었습니다. 비록 워크스페이스 위치를 변경할 수 있는 환경 변수(`SANDBOX_WORKSPACE`)가 존재하긴 했으나, 기본 설정을 사용하는 한 항상 프로젝트 내부 경로를 바라보고 있었습니다.

## 결정 (Decision)

Jupyter 커널 프로세스의 현재 작업 디렉터리(cwd)를 서버의 '프로젝트 루트 디렉터리'로 바인딩하기로 결정했습니다. 그리고 도구 설명문의 사용 규칙을 통해 모델에게 모든 파일 입출력 경로에 관습적으로 `./workspace/` 접두사를 붙여 작성하도록 안내했습니다. 이렇게 구성하면 모델이 코드에 작성한 `./workspace/chart.png` 상대 경로가 프로젝트 루트 하위의 실제 워크스페이스 디렉터리를 올바르게 가리키게 됩니다.

## 결과 (Consequences)

**초기에는 정상 동작했습니다**

워크스페이스가 프로젝트 디렉터리 내부에 위치하는 동안에는 명세서의 코드 예제와 실제 파일시스템의 물리 동작이 정확히 일치하여 아무런 문제가 발생하지 않았습니다.

**환경 변수 설정을 변경하자 시스템이 붕괴되었습니다**

현업 사용자가 환경 변수 `SANDBOX_WORKSPACE`를 활용하여 워크스페이스를 프로젝트 디렉터리 외부(예: D 드라이브의 별도 분석 데이터 폴더)로 변경하자 치명적인 결함이 수면 위로 드러났습니다. 원래 이 환경 변수가 존재하는 목적 자체가 워크스페이스를 외부 폴더로 자유롭게 지정하기 위함이었는데도 심각한 경로 불일치가 발생한 것입니다.

- 모델이 작성한 코드가 `./workspace/chart.png`를 저장하면, 이는 커널의 작업 디렉터리인 프로젝트 루트 디렉터리를 기준으로 해석되어 기존 서버 폴더 하위에 파일이 생성되었습니다.
- 반면 파일 목록 조회 도구, 스크립트 실행 도구, 파일 저장 도구, 그리고 산출물 자동 탐지기는 모두 환경 변수로 지정된 외부 워크스페이스 디렉터리만을 바라보고 있었습니다.
- 그 결과 물리 디스크 어딘가에 파일은 생성되었으나, 샌드박스의 어떤 도구에서도 해당 파일이 감지되지 않는 사태가 벌어졌습니다. 최종 사용자의 시야에는 생성된 파일이 감쪽같이 증발해 버린 것으로 보였습니다.

동시에 유사한 경로 참조 버그들이 추가로 발견되었습니다. 상대 경로로 지정된 `SANDBOX_WORKSPACE`가 MCP 서버를 구동한 호스트 런처의 임의 작업 디렉터리를 기준으로 해석되어 실행 환경마다 엉뚱한 폴더를 가리켰으며, 워크스페이스가 프로젝트 외부에 있을 때 산출물 링크가 절대 경로로 조립되어 마크다운에 `./D:/...`와 같이 완전히 깨진 링크가 생성되기도 했습니다.

**핵심 아키텍처 교훈**

시스템 내부에서 "상대 경로를 해석하는 기준점(기준 디렉터리)"이 둘 이상으로 분열되어 있으면 언젠가 반드시 결함이 폭발합니다. 본 결정에서는 커널이 경로를 해석하는 기준점(프로젝트 루트 디렉터리)과 MCP 도구들이 파일을 탐색하는 기준점(환경 변수로 지정된 워크스페이스)이 서로 분리되어 있었습니다. 기본 설정 환경에서는 우연히 두 기준이 일치하여 결함이 숨어 있었을 뿐이었습니다.

이 설계적 결함은 이후 커널의 작업 디렉터리를 워크스페이스 내부로 완전히 일치시키는 [ADR-016](adr-016-kernel-cwd-workspace.md)에 의해 전면 대체되었습니다.
