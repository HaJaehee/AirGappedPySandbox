# ADR-005. 산출물 파일은 코드 실행 전후의 파일시스템 스냅샷을 비교하여 탐지합니다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0 (v0.4.1에서 링크 경로 상대화 규칙 보완)

관련 결정: [ADR-013](adr-013-shared-workspace.md), [ADR-014](adr-014-write-file-tool.md), [ADR-016](adr-016-kernel-cwd-workspace.md), [ADR-019](adr-019-side-venv-installs.md)

## 맥락 (Context)

실행된 코드가 차트 이미지 파일이나 CSV 데이터를 새롭게 생성하면, 해당 파일의 접근 링크를 LLM 반환 응답에 자동으로 첨부해 주어야 합니다. 그러기 위해서는 이번 단일 도구 호출 과정에서 워크스페이스 내에 정확히 어떤 파일이 새롭게 생성되거나 수정되었는지를 시스템이 확실히 감지해 낼 수 있어야 합니다.

당시 검토했던 주요 대안들은 다음과 같습니다.

1. **OS 파일시스템 실시간 감시 라이브러리를 사용합니다.** `watchdog`과 같은 외부 라이브러리를 연동하여 디렉터리 변경 이벤트를 실시간으로 수신하는 방식입니다. 하지만 외부 의존성이 추가되고 백그라운드 이벤트 리스너 스레드가 상시 가동되어야 하며, 어떤 파일 이벤트가 구체적으로 어느 도구 호출 요청에 귀속되는지 경계가 모호해집니다. 또한 운영체제마다 파일 I/O 이벤트 발생 순서가 미묘하게 다릅니다.
2. **실행될 Python 소스코드를 정적 분석(AST 파싱)합니다.** `plt.savefig()`나 `df.to_csv()` 등의 함수 호출 구문을 파싱하여 저장 파일명을 추출하는 방식입니다. 그러나 파일명이 동적 변수나 난수 표현식에 담겨 있거나 서드파티 라이브러리 내부에서 간접적으로 파일이 생성되는 경우에는 파일명을 추출할 방법이 없습니다.
3. **모델에게 생성한 파일명을 프롬프트로 보고하도록 요구합니다.** 추론 능력이 취약한 소형 모델의 자율적인 보고는 환각이 잦아 결코 신뢰할 수 없습니다.
4. **코드 실행 직전과 직후의 파일시스템 스냅샷을 촬영하여 차이를 대조합니다.** 구조가 매우 단순하고 결과가 완벽하게 결정론적(Deterministic)입니다.

## 결정 (Decision)

코드 실행 직전과 직후에 워크스페이스 디렉터리 전체를 재귀적으로 스캔하여, 각 파일마다 `(최종 수정 일시, 파일 크기)` 튜플 메타데이터를 기록하는 가벼운 스냅샷을 생성하기로 결정했습니다. 실행 직후 두 스냅샷의 차이점(Diff)을 대조하여, 새롭게 생성되었거나 메타데이터가 변경된 파일들을 최신 수정순으로 정렬하여 최종 산출물 목록으로 확정합니다.

산출물 중 이미지 확장자(`png`, `jpg`, `jpeg`, `gif`, `svg`, `webp`, `bmp`)를 가진 파일은 AnythingLLM 화면에 즉각 시각화되도록 마크다운 이미지 태그(`![filename](./workspace/filename)`)로 렌더링하고, 기타 일반 데이터 파일은 다운로드 가능한 마크다운 링크로 조립합니다. 링크 경로는 서버 디렉터리 기준의 상대 경로를 사용합니다. v0.4.1부터는 워크스페이스가 서버 디렉터리 외부에 배치되더라도 절대 경로를 노출하지 않고 일관된 `workspace/<파일명>` 형태를 유지하도록 정규화했습니다. Windows 환경에서 절대 경로를 그대로 조합할 경우 `./D:/...`와 같이 잘못 깨진 링크가 생성되는 버그가 있었기 때문입니다.

## 결과 (Consequences)

**얻게 된 이점**

- 외부 라이브러리 없이 Python 표준 라이브러리(`os`, `pathlib`)만으로 완벽히 구현되었습니다. 폐쇄망에 반입해야 할 외부 종속성이 하나 더 줄어들었습니다.
- 감지 결과가 지극히 명확하고 결정론적입니다. 특정 도구 호출의 시작 시점과 종료 시점 사이에 파일시스템에서 변경된 물리적 차이 그 자체가 정확한 산출물이 됩니다.
- 동일한 스냅샷 탐지 모듈을 파일 저장 도구(`write_workspace_file`)에서도 완벽히 재사용합니다. 디스크에 쓴 파일이 스냅샷 차이에 나타나지 않을 경우 파일시스템 I/O 실패를 즉각 감지하고 경고할 수 있습니다([ADR-014](adr-014-write-file-tool.md)).

**감수한 트레이드오프**

- 파일 스캔 비용이 워크스페이스 내에 존재하는 전체 파일 개수에 정비례합니다. 만약 파일이 수만 개 이상 쌓여 있는 폴더를 워크스페이스로 지정하면 매 도구 호출마다 스냅샷 촬영 시간이 길어져 시스템이 느려집니다. 추가 설치용 사이드 venv 디렉터리를 워크스페이스 경계 바깥으로 분리한 이유가 바로 여기에 있습니다([ADR-019](adr-019-side-venv-installs.md)).
- 파일이 삭제된 이벤트는 산출물로 보고하지 않습니다.
- 파일의 수정 시각과 파일 크기가 우연히 둘 다 정확히 일치하는 극단적인 내용 변경은 감지하지 못할 수 있습니다. (실무 데이터 분석 환경에서는 거의 발생하지 않는 예외입니다.)
- 전체 워크스페이스 디렉터리를 대조하므로, 서로 다른 두 대화 세션의 코드가 완전히 동일한 시각에 동시 실행될 경우 상대방 대화가 생성한 파일이 내 산출물 목록에 함께 첨부될 수 있는 이론적 가능성이 있습니다([ADR-013](adr-013-shared-workspace.md)).
