# ADR-005. 산출물은 실행 전후 스냅샷을 비교해 찾는다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0 (v0.4.1에서 링크 경로 규칙 보완)

관련 결정: [ADR-013](adr-013-shared-workspace.md), [ADR-014](adr-014-write-file-tool.md), [ADR-016](adr-016-kernel-cwd-workspace.md), [ADR-019](adr-019-side-venv-installs.md)

## 맥락 (Context)

코드가 차트 이미지나 CSV 파일을 만들면, 그 파일의 링크를 응답에 붙여 돌려줘야 한다. 그러려면 이번 실행이 어떤 파일을 만들었는지 알아내야 한다.

검토한 선택지는 다음과 같다.

1. **파일 시스템 감시자.** watchdog 같은 라이브러리로 폴더의 변경 이벤트를 받는다. 추가 의존성이 생기고, 이벤트를 받는 스레드가 필요하며, 어느 이벤트가 어느 호출에 속하는지 경계가 흐릿하다. 운영체제마다 동작도 조금씩 다르다.
2. **코드를 분석한다.** `savefig`나 `to_csv` 호출을 찾아 파일 이름을 뽑는다. 파일 이름이 변수에 들어 있거나 라이브러리 내부에서 파일을 만들면 잡을 수 없다.
3. **모델에게 말하게 한다.** 약한 모델의 보고를 믿을 수 없다.
4. **실행 전후 스냅샷을 비교한다.** 단순하고 결정적이다.

## 결정 (Decision)

실행 직전과 직후에 워크스페이스 전체를 재귀적으로 훑어, 파일마다 (수정 시각, 크기)를 기록한다. 두 기록을 비교해 새로 생기거나 달라진 파일을 최신순으로 산출물로 삼는다.

이미지 확장자(png, jpg, jpeg, gif, svg, webp, bmp)는 본문에 표시되는 Markdown 이미지로, 나머지는 Markdown 링크로 만든다. 링크 경로는 서버 폴더 기준의 상대 경로(`./workspace/chart.png`)다. v0.4.1부터는 워크스페이스가 서버 폴더 밖에 있어도 절대 경로 대신 `workspace/<이름>` 형태를 유지한다. 절대 경로를 쓰면 `./D:/...` 같은 깨진 링크가 만들어졌기 때문이다.

## 결과 (Consequences)

**좋아진 점**

- 표준 라이브러리만으로 구현된다. 폐쇄망에 들여갈 의존성이 하나 줄었다.
- 결과가 결정적이다. 호출 하나의 시작과 끝 사이에서 무엇이 바뀌었는지가 곧 산출물이다.
- 같은 부품을 파일 저장 도구가 재사용한다. 저장한 파일이 차이에 나타나지 않으면 조용한 실패로 경고할 수 있다([ADR-014](adr-014-write-file-tool.md)).

**치른 비용**

- 비용이 워크스페이스의 파일 수에 비례한다. 파일이 수만 개인 폴더를 워크스페이스로 쓰면 매 호출이 느려진다. 추가 설치용 venv를 워크스페이스 밖에 둔 것도 이 때문이다([ADR-019](adr-019-side-venv-installs.md)).
- 삭제된 파일은 보고하지 않는다.
- 수정 시각과 크기가 둘 다 변하지 않는 변경은 놓칠 수 있다. 현실에서는 드물다.
- 워크스페이스 전체를 비교하므로, 두 대화가 동시에 실행되면 상대 대화가 만든 파일이 내 산출물로 잡힐 수 있다([ADR-013](adr-013-shared-workspace.md)).
