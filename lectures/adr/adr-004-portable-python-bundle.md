# ADR-004. 실행 환경 전체를 독립된 포터블 Python 하나로 묶어 오프라인 반입합니다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0

v0.6.0에서 [ADR-019](adr-019-side-venv-installs.md)가 보완했습니다. 런타임에 패키지를 동적으로 추가할 수 있는 경로가 신설되었으나, 기본 데이터 사이언스 핵심 스택은 여전히 독립 포터블 Python 번들에 담아 사전 반입하는 정책을 유지합니다.

관련 결정: [ADR-001](adr-001-local-mcp-server.md), [ADR-003](adr-003-separate-interpreters.md)

## 맥락 (Context)

대상 업무용 PC는 외부 인터넷이 완전히 차단되어 있으며, 프로젝트 초기에는 사내 패키지 미러 저장소조차 존재하지 않았습니다. 사용자에게 로컬 관리자 권한이 없어 시스템 설치 프로그램을 구동하기도 어렵습니다. 반면 데이터 분석에 필요한 라이브러리는 30여 종에 달하며, 그중 상당수(numpy, scipy, PyMuPDF, pyzmq 등)는 운영체제 플랫폼별로 사전 컴파일된 C/C++ 네이티브 확장 바이너리를 포함하고 있습니다.

당시 검토했던 주요 대안들은 다음과 같습니다.

| 공급 방식 | 비교 검토 및 판단 결과 |
|---|---|
| WinPython 번들 | 임의의 디렉터리에 압축만 풀면 즉시 독립 실행됩니다. pip 패키지 관리자가 기본 내장되어 있어 빌드 PC에서 라이브러리를 사전 설치하기가 매우 수월합니다. 단, 번들 용량이 다소 큽니다. |
| 공식 python.org Embeddable 패키지 | 파일 크기가 가장 작습니다. 그러나 pip이 누락되어 있고 `site` 모듈이 비활성화되어 있어 설정 파일을 직접 수정하고 pip 부트스트랩을 별도로 진행해야 합니다. |
| conda-pack 아카이브 | Conda 환경 전체를 이동식으로 패키징할 수 있습니다. 하지만 사용자가 Conda 도구에 익숙해야 하며, 압축 해제 후 하드코딩된 절대 경로들을 보정하는 별도 스크립트 실행이 필요합니다. |
| 일반 virtualenv (venv) 통째 복사 | 호스트 머신의 절대 경로에 강하게 바인딩되어 있어 다른 디렉터리나 다른 PC로 복사하면 즉시 환경이 깨집니다. |
| 오프라인 휠(Wheel)만 반입 | 대상 PC에 이미 호환되는 Python 환경이 사전에 설치되어 있어야만 합니다. |

## 결정 (Decision)

**WinPython 3.13**(64비트, Python 3.13.13 기반)을 시스템의 공식 표준 런타임으로 채택했습니다. 인터넷이 연결된 외부 빌드 PC에서 커널용 데이터 라이브러리와 MCP 서버 구동 의존성을 모두 사전 설치하고, 서버 소스코드와 함께 단일 디렉터리로 구성하여 압축 아카이브를 제작합니다. 이 압축 파일을 사내 보안 승인을 거친 이동식 매체(USB 등)로 폐쇄망 PC에 전달하여 원하는 경로에 압축 해제한 뒤 사용하도록 구성했습니다.

사내망 반입 전에는 반드시 빌드 PC의 물리 네트워크 케이블을 분리한 완전 오프라인 상태에서 사전 점검 스크립트와 스모크 테스트를 통과해야 합니다. 빌드 PC는 대상 폐쇄망 PC와 운영체제 종류, CPU 비트 수, Python 마이너 버전이 완벽히 일치해야 합니다.

아울러 대상 PC에 이미 호환 가능한 표준 Python이 설치되어 있는 특수 환경을 위해, 서버 의존성 오프라인 휠(Python 3.11~3.13 호환, win_amd64, 총 69개 파일)과 오프라인 전용 설치 스크립트도 함께 패키징하여 제공합니다.

## 결과 (Consequences)

**얻게 된 이점**

- 사용자는 임의의 폴더에 압축을 해제하는 것만으로 즉시 구동할 수 있습니다. 일체의 OS 설치 권한이나 관리자 권한이 필요 없습니다.
- 외부 빌드 PC에서 철저히 오프라인 검증을 마친 완전한 바이너리 상태 그대로 대상 PC에 배포됩니다. "개발자 PC에서는 잘 돌았는데 배포 PC에서는 왜 안 되는가"라는 환경 차이 결함을 원천 차단합니다.

**감수한 트레이드오프**

- 최종 압축 번들의 크기가 약 3.47GB에 달합니다. (초기 명세 초안에는 개략적인 추정치로 "약 40GB"라고 기재되어 있었으나, 실제로 환경을 구축하고 실측한 뒤 2026-08-03에 문서 전체를 "4GB 포터블 번들"로 올바르게 수정했습니다. 직접 실측해 보기 전의 초기 추정치를 맹신해서는 안 된다는 중요한 교훈을 남겼습니다.)
- 기본 번들에 라이브러리를 추가하려면 외부 빌드 PC에서 처음부터 다시 패키징하여 전사 반입 심의를 거쳐야 했습니다. 사전에 어떤 라이브러리를 포함할지 기획 단계에서 확정해야 하는 부담이 컸으나, v0.6.0에서 사내 PyPI 미러가 신설되면서 이 부담을 크게 완화할 수 있었습니다([ADR-019](adr-019-side-venv-installs.md)).
- 타깃 플랫폼 규격이 `win_amd64`, Python 3.13 환경으로 엄격히 고정됩니다.
- Git 소스코드 저장소에는 수 기가바이트에 달하는 WinPython 폴더, 휠 아카이브, 압축 파일을 커밋하지 않습니다. 대신 상세한 오프라인 빌드 매뉴얼(`BUILD_PORTABLE_PACKAGE.md`)을 작성하여 형상 관리하고 있습니다.
