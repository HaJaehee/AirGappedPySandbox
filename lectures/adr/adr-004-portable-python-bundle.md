# ADR-004. 실행 환경 전체를 포터블 Python 하나로 묶어 반입한다

## 상태 (Status)

채택됨 (Accepted) · 2026-07-23, v0.1.0

v0.6.0에서 [ADR-019](adr-019-side-venv-installs.md)가 보완했다. 런타임에 패키지를 추가할 길이 생겼지만, 기본 스택은 여전히 포터블 Python에 담아 반입한다.

관련 결정: [ADR-001](adr-001-local-mcp-server.md), [ADR-003](adr-003-separate-interpreters.md)

## 맥락 (Context)

대상 PC에는 인터넷이 없고, 당시에는 사내 패키지 저장소도 없었다. 사용자에게 관리자 권한이 없어 설치 프로그램을 돌리기도 어렵다. 그런데 필요한 라이브러리는 30종 가까이 되고, 그중 상당수(numpy, scipy, PyMuPDF, pyzmq 등)는 플랫폼별로 컴파일된 확장 모듈을 포함한다.

검토한 선택지는 다음과 같다.

| 방식 | 판단 |
|---|---|
| WinPython | 압축만 풀면 어디서든 실행된다. pip이 들어 있어 빌드 PC에서 라이브러리를 설치하기 쉽다. 크다 |
| python.org embeddable 패키지 | 가장 작다. pip이 없고 `site`가 꺼져 있어 설정 파일을 고치고 pip을 따로 설치해야 한다 |
| conda-pack | conda 환경을 옮길 수 있게 묶는다. conda에 익숙해야 하고, 풀고 나서 경로 보정 단계를 거쳐야 한다 |
| 일반 venv 복사 | 절대 경로에 묶여 있어 다른 위치로 옮기면 깨진다 |
| 오프라인 휠만 반입 | 대상 PC에 쓸 만한 Python이 이미 있어야 한다 |

## 결정 (Decision)

WinPython 3.13(64비트)을 기본 런타임으로 삼는다. 인터넷이 되는 빌드 PC에서 커널 라이브러리와 서버 의존성을 모두 설치하고, 서버 코드와 함께 한 폴더로 묶어 압축한다. 이 압축 파일을 승인된 매체로 대상 PC에 옮겨 풀고, 경로만 설정한다.

반입 전에는 빌드 PC의 네트워크를 끊은 상태에서 사전 점검과 스모크 테스트를 통과해야 한다. 빌드 PC는 대상 PC와 운영체제, 비트 수, Python 마이너 버전이 같아야 한다.

대상 PC에 이미 적당한 Python이 있는 경우를 위해, 서버 의존성의 오프라인 휠(Python 3.11~3.13, win_amd64, 69개)과 설치 스크립트도 함께 제공한다.

## 결과 (Consequences)

**좋아진 점**

- 압축을 푸는 것만으로 동작한다. 설치 권한이 필요 없다.
- 빌드 PC에서 검증한 것과 똑같은 것이 대상 PC에 도착한다. "내 PC에서는 됐는데"가 줄어든다.

**치른 비용**

- 크기가 약 3.47GB다. 명세 초안에는 "40GB"로 적혀 있었는데, 실제로 만들어 재 보고 2026-08-03에 문서 전체를 "4GB"로 바로잡았다. 추정치는 만들어 보기 전까지 믿지 말라는 작은 교훈이다.
- 라이브러리를 추가하려면 빌드 PC에서 다시 패키징해 반입해야 한다. 무엇을 넣을지 미리 확정해야 하는 부담이 크다. v0.6.0에서 사내 미러가 생기면서 이 부담이 줄었다([ADR-019](adr-019-side-venv-installs.md)).
- 플랫폼이 win_amd64, Python 3.13으로 고정된다.
- 소스 저장소에는 WinPython 폴더, 휠, 압축 파일을 커밋하지 않는다. 크기 때문이다. 대신 빌드 절차를 매뉴얼로 남겼다.
