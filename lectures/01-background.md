# 1장. 배경과 문제 정의

## 1.1 폐쇄망 안의 LLM

이 프로젝트가 놓인 곳은 인터넷이 완전히 차단된 사내망이다. 사내에 LLM 서버가 한 대 있고, 직원들은 사내망 안에서 이 모델에게 질문한다. 외부 API도, 웹 검색도, 패키지 저장소도 쓸 수 없다.

이 모델은 잘하는 일과 못하는 일이 뚜렷하다. 문서를 요약하거나 메일 초안을 쓰는 일은 곧잘 한다. 그런데 열두 자리 곱셈, 단위 환산, 3천 행짜리 엑셀의 합계, PDF 표에서 특정 값 찾기를 시키면 그럴듯한 숫자를 지어낸다. 언어 모델은 학습한 가중치를 바탕으로 다음 토큰을 고를 뿐, 실제로 계산하지는 않기 때문이다. 모델이 작을수록 이런 일이 잦다.

인터넷이 되는 환경이라면 흔한 해법이 있다. 모델에게 코드 실행 도구(Code Interpreter)를 붙여서 계산은 Python에게 맡기는 것이다. 모델은 "무엇을 어떻게 계산할지"를 코드로 쓰고, 숫자는 인터프리터가 낸다. 이 프로젝트도 결국 같은 방향으로 갔다. 다만 폐쇄망이라서 거기까지 가는 길이 간단하지 않았다.

## 1.2 서버를 고칠 수 없다

가장 정석적인 방법은 LLM 서버 쪽에 코드 실행 기능을 넣는 것이다. 하지만 사용자에게는 그 서버의 관리자 권한도, SSH 접속 권한도 없었다. 인프라 팀에 요청할 수는 있다. 그러나 승인과 작업에 시간이 오래 걸리고, 그렇게 들어간 기능은 한 번 정해지면 바꾸기 어렵다. 라이브러리 하나를 추가하려 해도 요청서를 다시 써야 한다.

그래서 질문을 바꿨다. 서버를 못 고친다면, 내가 통제할 수 있는 곳은 어디인가?

## 1.3 사용자 PC라는 우회로

답은 사용자 자신의 PC였다. 사용자는 PC에 AnythingLLM이라는 데스크톱 앱을 설치해 쓰고 있었고, 이 앱은 사내 LLM 서버에 OpenAI 호환 API로 붙어 있었다. 그리고 AnythingLLM의 에이전트 기능은 MCP(Model Context Protocol) 서버를 도구로 붙일 수 있다.

이 세 가지가 맞물리면서 길이 열렸다. 사용자 PC에 Python 실행 기능을 가진 MCP 서버를 띄우고 AnythingLLM에 등록한다. 그러면 LLM은 원격 서버에 그대로 있으면서, 계산이 필요할 때마다 AnythingLLM을 거쳐 사용자 PC의 Python에게 일을 시킬 수 있다. 원격 서버는 한 줄도 건드리지 않는다.

```
사용자 ─── AnythingLLM (사용자 PC) ─────── 사내 LLM 서버 (원격, 손댈 수 없음)
                 │
                 │  MCP
                 ▼
          Python 샌드박스 (사용자 PC, 이 프로젝트)
```

생각은 원격 LLM이 하고, 계산은 로컬 Python이 하는 구조다. 이 결정의 자세한 내용은 [ADR-001](adr/adr-001-local-mcp-server.md)에 정리했다.

## 1.4 무엇을 만들어야 했나

최초 명세가 요구한 것을 네 가지로 추리면 이렇다.

**상태를 유지하는 실행기.** 사용자가 100MB짜리 엑셀을 올려 두고 "월별 합계 보여 줘", "그중 3월만 그래프로", "전년 대비 증감률도"라고 이어서 묻는 상황을 떠올려 보자. 호출할 때마다 새 Python 프로세스를 띄우면 매번 그 엑셀을 처음부터 다시 읽어야 한다. 한 번 읽은 데이터는 대화가 이어지는 동안 메모리에 남아 있어야 한다.

**완전한 오프라인 동작.** 수치 계산(numpy, scipy, sympy), 표 분석(pandas), 차트(matplotlib, seaborn), 문서 파싱(PDF, 엑셀, CSV, XML, JSON, 워드, 마크다운)에 필요한 라이브러리를 미리 전부 챙겨 가야 한다. 대상 PC에서는 `pip install`을 할 수 없다.

**만들어진 파일 돌려주기.** 코드가 차트 이미지나 CSV를 만들면 LLM 응답에 그 파일의 링크가 자동으로 붙어야 한다.

**안전장치.** 파일 입출력은 정해진 작업 폴더(워크스페이스) 안에서 하고, 무한 루프에 빠진 코드는 시간 제한으로 끊어야 한다.

명세는 이것을 다섯 단계 로드맵(환경 구성, 상태 유지 코어, MCP 래퍼, 산출물 탐지, AnythingLLM 연동)으로 제시했고, 첫 릴리스인 v0.1.0이 다섯 단계를 모두 마쳤다.

## 1.5 설계를 좌우한 제약

이 프로젝트는 목표보다 제약이 설계를 더 많이 결정했다. 아래 표를 기억해 두면 이후 장에서 나오는 결정 대부분을 어느 제약에서 출발했는지 짚어 낼 수 있다.

| 제약 | 설계에 미친 영향 |
|---|---|
| 인터넷이 없다 | 실행에 필요한 모든 것을 한 폴더에 묶어 반입한다. 설치 프로그램 없이 압축만 풀면 도는 포터블 Python을 골랐다. |
| 관리자 권한이 없다 | 컨테이너나 전용 OS 계정 같은 강한 격리를 쓸 수 없다. 사용자 권한으로 도는 "관습적 샌드박스"를 받아들였다. |
| 모델이 약하다 | 규칙을 문장으로 설명하는 것만으로는 부족하다. 인자 모양과 응답 형식 자체를 모델이 실수하기 어렵게 만들었다. |
| AnythingLLM이 MCP 서버를 하나만 띄운다 | 여러 대화가 한 프로세스를 공유하므로, 대화마다 변수 공간을 나눠야 했다. |
| 클라이언트가 60초 뒤 요청을 끊는다 | 서버가 한 번에 붙잡고 있을 수 있는 시간을 그보다 짧게 잡아야 했다. |
| 대상 운영체제가 Windows다 | 일부 블로킹 호출은 인터럽트로 깨울 수 없어서 커널을 강제로 재시작하는 경로가 필요했다. |

위의 두 줄은 처음부터 알던 제약이다. 아래 세 줄은 만들고 운영하면서 부딪혀 알게 됐다. AnythingLLM의 단일 프로세스 문제는 v0.3.0을, 60초 제한은 v0.7.0을 낳았다. Windows 인터럽트 문제는 첫 릴리스 전 개발 중에 발견되어 v0.1.0부터 대비책이 들어가 있다. 가운데 "모델이 약하다"는 처음부터 알던 사실이지만, 그것이 설계에 얼마나 깊이 영향을 주는지는 나중에야 드러났다.

## 1.6 프로젝트가 걸어온 길

| 버전 | 날짜 | 무엇이 문제였고 무엇을 바꿨나 |
|---|---|---|
| v0.1.0 | 2026-07-23 | 최초 구현. 영속 커널, 산출물 탐지, MCP 도구 3종, WinPython 기반 포터블 패키지. |
| v0.2.0 | 2026-07-23 | 워크스페이스에 있는 `.py` 파일을 스크립트로 실행하는 도구 추가. |
| v0.3.0 | 2026-07-25 | 두 대화가 같은 변수 이름을 쓰면 서로 덮어쓴다는 사실을 발견. 대화마다 커널을 따로 두는 네임스페이스 도입. |
| v0.4.0 | 2026-08-04 | "이 코드를 파일로 저장해 줘"를 작은 모델이 번번이 실패. 저장 전용 도구 추가. |
| v0.4.1 | 2026-08-28 | 워크스페이스를 프로젝트 밖으로 옮기면 만든 파일이 사라지는 문제. 커널의 작업 폴더를 워크스페이스로 변경. |
| v0.5.0 | 2026-09-22 | 모델이 실패한 실행을 성공으로 보고. 실행 결과 판정 체계를 새로 짬. |
| v0.6.0 | 2026-09-22 | 사내망에 PyPI 미러가 생김. 별도 가상환경에 패키지를 설치하는 도구 추가. |
| v0.7.0 | 2026-09-22 | 미러가 멀쩡한데도 설치가 "Context server request timeout"으로 끝남. 모든 도구가 클라이언트 제한시간 안에 답하도록 변경. |

v0.1.0이 명세의 기능을 모두 갖춘 상태였다는 점에 주목하자. 이후의 변경은 대부분 새 기능이 아니라, 실제로 써 보니 드러난 문제를 고친 것이다. 특히 v0.4.0과 v0.5.0은 코드가 틀려서 생긴 문제가 아니었다. 코드는 설계대로 동작했는데 모델이 그 결과를 잘못 이해했다. 이 이야기는 4장에서 따로 다룬다.

## 생각해 볼 문제

1. LLM 서버에 코드 실행 기능을 직접 넣는 방식과 이 프로젝트의 방식을 비교해 보자. 사용자가 100명으로 늘어나면 각 방식에서 어떤 문제가 먼저 터질까?
2. "인터넷이 없다"와 "관리자 권한이 없다"는 둘 다 설치를 어렵게 만드는 제약이다. 두 제약이 설계에 남긴 흔적은 어떻게 다른가?
3. 변경 이력을 보면 "모델이 도구를 잘못 이해해서" 생긴 문제가 적지 않다. 이런 문제를 개발 단계에서 미리 발견하려면 어떤 시험을 했어야 할까?
