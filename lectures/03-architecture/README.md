# 3장. 아키텍처

이 장은 에어갭 Python 샌드박스의 아키텍처 문서다. 시스템 하나를 세 가지 관점으로 나누어 기술한다.

| 뷰 | 답하려는 질문 | 문서 |
|---|---|---|
| 정적 뷰 (Static View) | 시스템은 어떤 부품으로 이루어져 있고, 부품끼리 어떻게 연결되는가? | [01-static-view.md](01-static-view.md) |
| 동적 뷰 (Dynamic View) | 실행 중에 부품들이 어떤 순서로 무엇을 주고받는가? | [02-dynamic-view.md](02-dynamic-view.md) |
| 배포 뷰 (Deployment View) | 부품들이 어느 기계, 어느 프로세스, 어느 폴더에 놓이고, 어떻게 그곳에 도착하는가? | [03-deployment-view.md](03-deployment-view.md) |

관점을 나누는 이유는 한 장의 그림에 모든 것을 담으려 하면 아무것도 제대로 보이지 않기 때문이다. 예를 들어 "커널 풀"은 정적 뷰에서는 커널 여러 개를 소유하는 부품이고, 동적 뷰에서는 예비 커널을 새 대화에 넘겨주는 과정이며, 배포 뷰에서는 사용자 PC에 동시에 떠 있는 Python 프로세스 아홉 개다. 같은 대상을 다른 질문으로 비춰 보는 셈이다.

이 문서는 세 뷰가 공통으로 기대는 내용을 먼저 정리한다. 아키텍처를 이끈 요구와 제약, 다이어그램 표기법, 공통 용어다.

## 3.1 범위와 기준

- 대상 버전: v0.7.0
- 범위: MCP 서버, 서버가 띄우는 커널 프로세스, 파일 저장소(워크스페이스와 패키지 venv), 배포 패키지
- 외부 시스템으로 다루는 것: AnythingLLM, 사내 LLM 서버, 사내 PyPI 미러

## 3.2 아키텍처 드라이버

아키텍처는 기능 목록보다 품질 요구와 제약에 더 크게 좌우된다. 이 시스템의 드라이버를 정리하면 다음과 같다.

### 기능 요구

- LLM이 Python 코드를 실행하고 출력을 돌려받는다.
- 실행과 실행 사이에 변수, import, 불러온 데이터가 유지된다.
- 코드가 만든 파일을 자동으로 찾아 링크로 돌려준다.
- 워크스페이스의 파일을 나열하고, 텍스트를 파일로 저장하고, `.py` 파일을 스크립트로 실행한다.
- 필요하면 사내 미러에서 패키지를 설치한다(v0.6.0부터).

### 품질 속성

| 품질 속성 | 구체적인 기준 | 주로 대응하는 결정 |
|---|---|---|
| 응답성 | 후속 질문에서 파일을 다시 읽지 않는다. 새 대화의 첫 실행도 곧바로 시작한다 | 영속 커널([ADR-002](../adr/adr-002-persistent-jupyter-kernel.md)), 예비 커널([ADR-012](../adr/adr-012-kernel-pool-per-namespace.md)) |
| 오프라인 자급성 | 인터넷 없이 모든 기능이 동작한다 | 포터블 Python([ADR-004](../adr/adr-004-portable-python-bundle.md)) |
| 가용성 | 어떤 코드를 실행했든 다음 호출은 응답하는 커널을 받는다 | 타임아웃과 강제 재시작([ADR-008](../adr/adr-008-conventional-sandbox-timeouts.md)) |
| 격리 | 대화끼리 변수가 섞이지 않는다. 파일 도구는 워크스페이스 밖을 건드리지 않는다 | 네임스페이스([ADR-011](../adr/adr-011-namespace-argument.md), [ADR-012](../adr/adr-012-kernel-pool-per-namespace.md)), 경로 검증([ADR-014](../adr/adr-014-write-file-tool.md)) |
| 정직성 | 서버가 확인하지 못한 성공을 성공이라고 말하지 않는다 | 실행 판정([ADR-017](../adr/adr-017-execution-verdict.md)), 설치 검증([ADR-020](../adr/adr-020-verify-installs-directly.md)) |
| 모델 친화성 | 약한 모델도 도구를 틀리지 않고 쓴다 | 설명문 규칙([ADR-007](../adr/adr-007-rules-in-tool-descriptions.md)), 저장 전용 도구([ADR-014](../adr/adr-014-write-file-tool.md)) |
| 되돌림 가능성 | 런타임에 바꾼 것은 폴더 하나만 지우면 원래대로 돌아간다 | 별도 venv([ADR-019](../adr/adr-019-side-venv-installs.md)) |

"정직성"과 "모델 친화성"은 흔히 보는 품질 속성 목록에는 잘 나오지 않는다. 이 시스템의 직접 사용자가 사람이 아니라 LLM이라서 생긴 항목이다. LLM이 결과를 잘못 읽으면 그 오해가 그대로 사람에게 전달된다. v0.4.0 이후 변경의 대부분이 이 두 속성에서 나왔다.

### 제약

- 대상 PC에는 인터넷이 없다. 사내망에는 LLM 서버와, 나중에 생긴 PyPI 미러만 있다.
- 사용자는 대상 PC에도 LLM 서버에도 관리자 권한이 없다.
- MCP 클라이언트는 AnythingLLM이며, 서버 프로세스를 하나만 띄워 모든 대화가 공유한다.
- MCP 클라이언트는 60초가 지나면 요청을 취소한다.
- 대상 운영체제는 Windows 64비트다.
- 모델은 작고 약하다. 긴 규칙을 끝까지 따르지 못하고, 응답의 처음과 끝에 크게 기댄다.

## 3.3 C4 모델로 그리기

정적 뷰, 그리고 동적·배포 뷰의 대표 그림은 C4 모델로 그렸다. C4는 소프트웨어 구조를 확대 수준이 다른 네 단계 그림으로 설명하는 방법이다. 지도 앱에서 나라, 도시, 동네, 건물 순으로 확대해 들어가는 것과 비슷하다.

| 단계 | 보여 주는 것 | 이 문서에서 |
|---|---|---|
| 1. 시스템 컨텍스트 | 시스템을 상자 하나로 놓고, 주변의 사람과 외부 시스템을 그린다 | 정적 뷰 |
| 2. 컨테이너 | 시스템을 이루는, 따로 실행되거나 따로 저장되는 단위 | 정적 뷰 |
| 3. 컴포넌트 | 컨테이너 하나의 내부 구성 요소 | 정적 뷰 |
| 4. 코드 | 클래스나 함수 수준 | 다루지 않는다 |

C4에서 말하는 "컨테이너"는 Docker 컨테이너가 아니다. 독립적으로 실행되는 프로세스나 데이터 저장소를 가리킨다. 이 시스템에서는 MCP 서버 프로세스, 커널 프로세스들, 워크스페이스 폴더, 패키지 venv 폴더, 사전 점검 도구가 컨테이너다.

C4에는 네 단계 말고도 보조 그림이 있다. 특정 시나리오에서 요소들이 번호 순서대로 주고받는 모습을 그리는 동적 다이어그램, 요소들이 어떤 인프라 위에 놓이는지 그리는 배포 다이어그램이다. 각각 동적 뷰와 배포 뷰에서 쓴다. C4로 표현하기 어려운 분기, 반복, 시간 순서는 시퀀스 다이어그램, 순서도, 상태 다이어그램으로 보충했다.

다이어그램은 Mermaid 문법으로 작성했다. Mermaid의 C4 지원은 아직 실험 단계라 자동 배치가 어색할 때가 있다. 상자의 위치보다는 상자와 화살표에 적힌 내용을 보면 된다.

## 3.4 공통 용어

| 용어 | 뜻 |
|---|---|
| 커널 | 사용자 코드를 실제로 실행하는 IPython 프로세스. 변수를 메모리에 들고 있다 |
| 네임스페이스 | 대화 하나에 대응하는 격리 단위. 네임스페이스마다 커널이 하나씩 있고, `ns-3fa1` 같은 id를 가진다 |
| 예비 커널 | 아직 어느 네임스페이스에도 속하지 않은 채 미리 켜 둔 커널. 새 네임스페이스가 생기면 이것을 가져간다 |
| 워크스페이스 | 입력 파일과 출력 파일이 놓이는 폴더. 모든 네임스페이스가 공유하며, 커널의 작업 디렉터리이기도 하다 |
| 산출물 | 실행 중에 워크스페이스에 새로 생기거나 바뀐 파일 |
| 판정 | 실행 결과를 서버가 등급으로 매긴 것. 응답 첫 줄의 `execution_status` 값 |
| 사건 장부 | 예외 없이 지나가는 실패(스레드 예외, 하위 프로세스의 비정상 종료)를 커널 안에서 기록해 두는 목록 |
| 도구 예산 | 도구 호출 하나가 응답을 미룰 수 있는 최대 시간. 기본 45초 |

전체 용어는 [용어집](../glossary.md)에 있다.

## 3.5 뷰와 결정의 연결

각 뷰가 설명하는 구조에는 근거가 된 ADR이 하나 이상 있다. 본문에 번호를 달아 두었으니 함께 읽기를 권한다. ADR 전체 목록과 결정 사이의 관계도는 [adr/README.md](../adr/README.md)에 있다.
